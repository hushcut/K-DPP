# 탄소 저장 구조 구현 1단계

2026-09-11. 설계서 전체 구현이 아닌 저장 구조 기반 작업이다.

## 구현한 내용

- material_factors, calculation_profiles, profile_factors 모델과 테이블.
- analysis_results의 nullable 계산 버전·정책·근거 JSON·중복 방지 키 컬럼.
- 계수 key/version 및 정책 key/version 유일성, 검토 상태 제약.
- 사용자/요청 키 유일 인덱스. 실제 재요청 처리 서비스는 다음 단계다.
- 기존 source/description 컬럼을 보존하는 추가 방식 마이그레이션.
- database import 시 DB 생성·수정 제거.
- seed는 없는 소재만 추가하고 기존 값과 별칭을 유지.

## 전환 상태

기존 앱 호환을 위해 lifespan → seed_materials → ensure_schema 호출은 유지한다. 따라서 **서버 시작 시에는 여전히 스키마를 준비한다**. 설계서의 명시적 마이그레이션 전용 시작 방식과 완전한 버전 검사기는 후속 단계다. schema_migrations의 1은 현재 기반 스키마 표식이며 미래 버전 거부 로직은 아직 없다.

새 컬럼은 null 허용이므로 기존 API가 생성한 기록도 정상 저장된다. 기존 계산 API는 아직 새 정책을 선택하거나 근거 JSON을 채우지 않는다. 선정 적합성·정책 활성화·Decimal 검증은 v2 서비스 계층에서도 수행한다. SQLite 연결마다 외래키 검사를 활성화해 존재하지 않는 정책·소재·계수 연결을 거부한다.

스키마 버전 2에서는 DB 트리거로 선정 계수와 공개 정책의 불변성을 추가했다. 정책은 draft로 만든 뒤 호환되는 selected 계수를 연결해야 active로 바꿀 수 있다. 같은 용도의 active 정책은 하나만 허용한다. selected 계수 및 active/retired 정책 구성은 수정·삭제할 수 없고, active에서 retired로 종료하는 전환만 허용한다. 따라서 변경이 필요하면 기존 행을 덮어쓰지 않고 새 버전을 만들어야 한다.

`carbon.policy_admin` 명령은 JSON manifest의 소재·버전·출처·범위 호환성을 먼저 검사한다. `--apply`가 없으면 읽기 전용 검증으로 끝나며, 적용할 때는 정책·계수·연결·활성화를 한 트랜잭션으로 처리한다. 실제 문헌값의 승인 여부는 명령이 대신 판단하지 않는다.

## 검증

전용 pytest DB 및 tmp_path에 생성한 DB만 사용한다. 구형 출처 컬럼·결과 보존, 마이그레이션 재실행, import 무변경, seed 보존, 계수 버전 유일성, 외래키 거부, 선정 계수·공개 정책 수정 거부 및 스냅샷 왕복 저장을 시험한다. 사용자 DB에는 마이그레이션을 실행하지 않았다.

실제 적용 전 서버 쓰기 중지, SQLite 일관 백업과 복원 시험이 필요하다. 현재 모듈은 `python database.py`로 명시적으로 실행 가능하지만 이 명령은 설정된 DB를 변경하므로 테스트 안내용 자동 실행에 포함하지 않는다.
