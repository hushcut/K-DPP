# OCR 비교 실험 전체 요약 및 Claude 인계

작성일: 2026-10-27 (한국 시간)  
범위: 요한·승우의 독립 OCR 실험 논의부터 PaddleOCR/EasyOCR 20장 비교, GLM-OCR/PaddleOCR-VL 50장 비교, Google Vision 캐시 재평가까지.

> 이 문서는 기존 대화와 로컬 산출물을 정리한 참고 자료입니다. 원래 계획서의 향후 작업을 현재 실행하라는 요청이 아닙니다. 현재 요청은 요약·인계이며, 추가 학습·설치·서비스 변경·새 API 호출·Git 변경을 자동으로 시작하지 않습니다.

## 1. 먼저 볼 결론

- 목적은 기존 Google Vision 서비스를 즉시 교체하는 것이 아니라, 향후 OCR 호출 비용에 대비해 실사용 가능한 무료 OCR 후보를 검토하는 것입니다.
- 사용자가 지정한 동재 실사진 폴더의 **50장 전체**를 GLM-OCR과 PaddleOCR-VL 1.6으로 실행했습니다. AI로 만든 약 200장은 이번 비교에 사용하지 않았습니다.
- 동일한 원본 사진과 동일한 텍스트 전용 파서로 대표 조성을 비교하면 **Vision 36/48(75.0%), GLM 25/48(52.1%), PaddleOCR-VL 19/48(39.6%)**입니다.
- 좌표·복수 후보·재시도를 포함한 **기존 Vision 서비스 전체 경로**의 저장 캐시 재검증 기록은 **43/48(89.6%)**입니다. 위의 공통 텍스트 파서 비교와 조건이 다릅니다.
- 현재 서비스는 Vision을 유지하고, 이번 두 무료 후보 중 추가 개선 대상으로는 GLM을 우선 검토하는 것이 타당하다는 판단입니다. 곧바로 서비스 대체가 가능하다는 결론은 아닙니다.
- 이번 요한 실험에서 모델 추가 학습은 하지 않았습니다. 승우 인계 문서에 기록된 소규모 학습 완료와 구분해야 합니다.
- 사용자는 PC별 성능 차이를 고려해, 시간 차이가 매우 크지 않으면 **처리 시간보다 정확도를 우선**하겠다고 했습니다.

1. 처음에는 요한과 승우가 별도로 진행할 OCR 실험의 계획서와 인계 문서를 읽고 정리했습니다. 즉시 학습을 시작하는 요청은 아니었습니다.

4. 기존 PaddleOCR의 검출·줄 방향 설정을 개선하고 EasyOCR 및 Vision 저장 캐시와 비교했습니다. 사용자는 이 결과를 Claude에서도 검토하고, 주말 진행 내용을 공유했습니다.
5. 기존 PaddleOCR/EasyOCR 외에 보조용이 아닌 실사용 후보를 원해 GLM-OCR과 PaddleOCR-VL 1.6을 비교 대상으로 추가했습니다.
6. 두 모델에 같은 기존 20장을 실행한 뒤, 사용자의 요청에 따라 나머지 30장을 실행했습니다. 두 모델의 전체 실행 수는 각각 50장입니다.
7. Vision도 같은 50장 원본 캐시를 동일 파서로 오프라인 재채점해 비교했습니다. 새 Vision 호출은 없었습니다.
8. 이 문서는 위 결과 전체를 Claude가 확인할 수 있도록 묶은 인계 자료입니다. 후속 학습이나 서비스 변경은 아직 실행하지 않았습니다.

## 5. 평가 방법과 분모가 다른 이유

### 5.1 핵심 문구 평가

소재명·숫자·퍼센트·부위·조성 표제 등 사진별 필수 토큰을 모두 포함했는지 봅니다.

- 공백은 무시하고 대소문자는 구분합니다. 같은 토큰의 기대 반복 횟수도 확인합니다.
- 먼저20장은 기존 토큰 초안을 유지했고, 추가30장은 모델 출력 내용을 열어 보기 전에 원본을 확인해 새 초안을 고정했습니다.
- **핵심 토큰 초안 기준**이지 전체 문자열 완전일치율이나 CER이 아닙니다.
- 토큰을 모두 포함해도, 추가 오독·중복·잘못된 줄 순서·소재와 숫자의 연결 오류를 놓칠 수 있습니다.
- 서로 다른 초안 목록을 합산한 수치이므로 탐색적 참고치로 해석해야 합니다.
- **DJ014와 DJ037**은 매우 희미해 핵심 문구 정답 확정을 보류했습니다. 따라서 글자 평가 대상은48장입니다.

### 5.2 대표 조성 평가

모든 엔진의 텍스트를 같은 서비스 파서 `c49205c`의 **`parse_label(text)` 경로**에 넣습니다. 기존 정답표의 대표 조성과 소재·비율이 완전히 같은지 비교하며 비율 허용오차는0입니다.

- 전체 부위의 모든 조성이 맞았다는 뜻이 아닙니다. 대표 부위·선택 부위 정보는 원본 결과에서 별도로 확인해야 합니다.
- 현재 파서는 Vision 응답을 바탕으로 개선돼 출력 배열·주변 잡음·표현 차이의 영향을 받을 수 있습니다.
- **DJ030과 DJ046**은 `Adorable40% / Chic30% / Dream30%`처럼 실제 소재명이 없는 라벨이라 조성 평가에서 제외합니다. 이 두 사진의 글자 평가는 포함합니다.
- 따라서 조성 평가 대상도48장이지만, **글자 평가48장과 제외 사진이 다릅니다.**

### 5.3 실행 이상과 오답 확정

- 생성 출력이1,024토큰 제한에 도달한 결과는 일부 정답 토큰이 있어도 정상 완료 판독으로 세지 않았습니다.
- 프로그램 실행 예외와 잘못 읽은 텍스트, 반복 출력은 별개로 기록했습니다.
- “틀린 조성 확정”은 파서가 성공 상태로 소재를 반환했지만 정답과 다른 경우입니다.
- 이 값이0건이어도 OCR 원문 오류·환각이 없다는 뜻은 아닙니다. 많은 실패는 파서가 조성을 확정하지 못한 경우입니다.

## 6. 최종50장 비교 — 동일 텍스트 파서 조건

| 모델 | 핵심 문구 일치 | 대표 조성 일치 | 조성 미확정 | 틀린 조성을 성공으로 확정 |
|---|---:|---:|---:|---:|
| Google Vision 원본 캐시 | 27/48 | **36/48, 75.0%** | 12 | 0 |
| GLM-OCR | 26/48 | **25/48, 52.1%** | 23 | 0 |
| PaddleOCR-VL 1.6 | 23/48 | **19/48, 39.6%** | 29 | 0 |

Vision은 2026-10-10 저장 캐시에서 사진 SHA-256과 같은 **원본 입력의 text**만 사용했습니다. 전처리·재시도 후보에서 정답에 맞는 결과를 골라 합치지 않았습니다. 기존20장의 Vision 텍스트·핵심 문구·파서 판정이 이전 결과와 사진별로 재현되는 것도 확인했습니다. 새로운 Vision API 호출은0회입니다.

GLM은 Vision보다 대표 조성을11장 적게 맞혔지만, 이번 두 VLM 후보 중에서는 PaddleOCR-VL보다6장 더 맞혔습니다. 핵심 문구 수치가 비슷하다고 서비스 결과까지 비슷한 것은 아닙니다. 반대로 파서 점수 차이 전체를 OCR 모델 자체의 순수 인식 차이라고 단정할 수도 없습니다.

### 6.1 Vision 서비스 전체 경로는 별도 참고

| Vision 평가 경로 | 대표 조성 일치 |
|---|---:|
| 원본 text만 공통 parse_label에 입력 | 36/48, 75.0% |
| 기존 서비스 전체 경로의 저장 캐시 재검증 기록 | **43/48, 89.6%** |

서비스 전체 경로는 단어 좌표·복수 OCR 후보·전처리·소재 영역·재시도 등을 이용하므로 공통 텍스트 경로와 조건이 다릅니다. 43/48은 **2026-10-10 저장 캐시 재검증** 기록이며, 오늘 새로 API를 호출한 점수가 아닙니다. 그 기록의 소재와 부위 동시 일치는42/48입니다.

주의: 정답표로 사용하는 `graded_results.json`에 포함된 당시 서비스 결과는42/48입니다. 이후 DJ037 보완의 별도 재검증 산출물에서43/48로 개선됐습니다. 원본 text 공통 평가36/48, 당시 서비스42/48, 보완 후 캐시 재검증43/48을 섞지 않아야 합니다.

## 8. 관찰한 실패 유형

### 8.1 전통 PaddleOCR와 EasyOCR

- 전통 PaddleOCR의 단독 검출 모듈은 기본적으로 긴 변960px로 줄여 검출했습니다. 승우 스크립트의1600px 입력 축소와 별개입니다. 원본 크기 검출 설정을 쓰자 촘촘한 줄 병합이 줄었습니다.
- 세로 상자를 한 방향으로만 돌리면 글자가 거꾸로 들어갈 수 있었습니다. 줄 방향 분류 PP-LCNet_x1_0_textline_ori가 기존09번을 개선했습니다.
- 개선 설정은 줄 방향 분류와 `limit_type=min, limit_side_len=64`입니다. 직접 조립한 검출·자르기·인식 경로로, 공식 전체 파이프라인과 완전히 같지는 않습니다.
- 남은 실패는 바르게 잘린 줄의 소재·부위·숫자 오인식이 많았습니다. 예: 겉감→걸감·결감, 폴리에스터→플리에스터, 65%→650.
- EasyOCR는 퍼센트를96·9 등으로 읽는 문제가 많았고, 회전 옵션이 바른 줄까지 뒤집어 성능이 낮아졌습니다.
- 승우 인계 문서의 “5단계 인식 모델 본 학습”이 개선 방향으로 거론됐지만, 이번 비교에서 실행하지 않았습니다.
