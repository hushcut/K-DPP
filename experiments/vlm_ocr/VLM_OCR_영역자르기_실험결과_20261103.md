# GLM-OCR·PaddleOCR-VL 조성 영역 자르기 실험 (3단계)

작성: 2026-11-03 · 작성자: 김요한 · 기준: `kyh/new-ocr`, 서비스 코드 `c49205c`(복사본 사용) · 범위: DJ 48장(설정 조정용). QA 확인은 5단계에서 합니다.

## 1. 요약

- **질문:** 사진 전체를 줄여 읽는 대신 조성 영역만 잘라 읽으면 무료 VLM의 정확도와 시간이 나아지는지 확인했습니다.
- **결과(DJ 48장, 조성 정답 수):**

| 입력 | GLM-OCR | PaddleOCR-VL | 틀린 성공 |
|---|---:|---:|---:|
| 전체 사진(기준) | **25** | 18 | 0 |
| Vision 좌표 소재 영역 + 기울기 보정 | 23 | **22** | 0 |
| PaddleOCR 좌표 소재 영역 + 기울기 보정 | 22 | 21 | 0 |
| 글자 상자 전체 영역 | 22 | 19 | 0 |
| 참고: Vision 원본 글자 36 · Vision 서비스 전체 경로 44 | | | 0 |

- **정확도:** 뚜렷한 개선이 없습니다. GLM-OCR은 2~3장 줄고 PaddleOCR-VL은 1~4장 늘어, Vision과의 격차는 그대로입니다.
- **VLM 읽기 시간:** 소재 영역은 줄었습니다(같은 사진 중앙값 GLM-OCR 약 25초→12~13초, PaddleOCR-VL 약 15초→7~8초). 출력 토큰이 절반 이하로 줄어든 영향으로 보입니다. 다만 전체 사진 쪽 측정에 배터리 상태가 섞여 있어 실제 폭은 이보다 작을 수 있습니다(6절).
- **무료 경로 전체 시간은 오히려 늘었습니다.** 무료 엔진만 쓰려면 PaddleOCR로 영역을 찾아야 하는데, 이 시간(중앙값 18초)을 더하면 전체 사진을 바로 읽는 것보다 느립니다(PaddleOCR-VL 14.3초→28.4초, GLM-OCR 24.6초→36.6초). 이 노트북 CPU에서는 자르기의 이득이 없습니다.
- **Vision 보조로도 근거가 약합니다.** Vision 서비스 경로가 실패한 DJ 4장은 어떤 설정도 맞히지 못했습니다.
- **QA에서는 다를 수 있습니다.** DJ는 사진이 작아 전체 사진 축소 손실이 작습니다(4.5). 5단계 QA 확인에 PaddleOCR 좌표 소재 영역 + 기울기 보정을 후보로 넣습니다.

## 2. 실험 방법

| 항목 | 내용 |
|---|---|
| 사진 | DJ 50장 실행, 조성 평가 48장(DJ030·DJ046 제외). 정답표는 1단계와 같음 |
| 모델 설정 | 1단계와 같음. GLM-OCR 50만 화소, PaddleOCR-VL 25만 화소, CPU 8스레드, 반복 감지, 출력 상한 1,024토큰, 기본 프롬프트 |
| 평가 | `parse_label(text)`와 정답표의 소재·비율 일치(허용 오차 0). `raw` 기준. 틀린 성공은 파서 성공인데 정답과 다른 경우 |
| 새 호출 | Vision 0회. 좌표는 저장된 서비스 OCR 캐시의 원본 후보만 사용 |
| 못 찾은 사진 | 전체 사진 결과로 대신해 48장 모두 채점 |

자른 영역은 세 가지입니다. 자른 이미지는 크기를 그대로 두고 무손실로 저장한 뒤, 모델 화소 상한을 넘을 때만 줄였습니다.

| 영역 | 만드는 방법 | 찾은 사진 | 면적 비율(중앙값) |
|---|---|---:|---:|
| Vision 좌표 소재 영역 | Vision 단어 좌표 → 서비스 `find_material_region` | 47/48 | 15% |
| PaddleOCR 좌표 소재 영역 | PaddleOCR 단어 좌표 → 같은 코드. 무료 경로 | 36/48 | 26% |
| 글자 상자 전체 영역 | PaddleOCR 글자 상자를 모두 감싸고 글자 높이 1배 여백. 글자 내용을 쓰지 않음 | 48/48 | 42% |

- **기울기 보정:** 글자 기울기가 5도 이상이면 서비스 소재 영역 후보처럼 영역을 돌렸습니다. Vision 좌표 10장, PaddleOCR 좌표 6장이 해당합니다(옆으로 누운 라벨 포함). 나머지 사진은 같은 이미지이므로 기존 결과를 씁니다.
- **영역 품질:** 정답 소재명과 비율 단어(Vision이 읽은 단어 기준)가 영역에 모두 들어온 사진은 Vision 좌표 43/44장, PaddleOCR 좌표 34/35장입니다. 표본 6개는 눈으로도 확인했습니다.
- **기준 수치 확인:** 같은 스크립트로 전체 사진을 다시 채점해 GLM-OCR 25, PaddleOCR-VL 18, Vision 원본 글자 36이 1단계와 같게 나왔습니다.

| Vision 좌표 소재 영역 + 기울기 보정 | 23 | +2 −4 | 22 | +6 −2 |

- 최대 메모리는 전체 사진과 비슷합니다(GLM-OCR 약 5.0GB, PaddleOCR-VL 약 4.1GB).

### 3.3 영역 찾기까지 합친 사진당 시간

48장 각각의 시간을 더한 값입니다. PaddleOCR 시간은 2단계 원본 후보 측정값과 이번 검출 측정값을 썼습니다. 영역을 못 찾은 사진은 전체 사진 읽기로 대신합니다.

| 경로 | 정답 | 중앙값(초) | 최대(초) | 10초 이내 | 25초 이내 |
|---|---:|---:|---:|---:|---:|
| GLM-OCR 전체 사진 | **25** | **24.6** | 79.6 | 0 | **25** |
| PaddleOCR 읽기 → GLM-OCR 소재 영역 | 22 | 36.6 | 85.5 | 0 | 4 |
| PaddleOCR 검출 → GLM-OCR 글자 상자 전체 | 22 | 47.3 | 86.6 | 0 | 2 |
| PaddleOCR-VL 전체 사진 | 18 | **14.3** | 86.8 | 12 | **40** |
| PaddleOCR 읽기 → PaddleOCR-VL 소재 영역 | 20 | 28.4 | 72.6 | 0 | 14 |
| PaddleOCR 읽기 → PaddleOCR-VL 소재 영역 + 기울기 보정 | 21 | 29.2 | 72.6 | 0 | 14 |
| PaddleOCR 검출 → PaddleOCR-VL 글자 상자 전체 | 19 | 32.0 | 53.3 | 0 | 12 |

- 무료 경로는 PaddleOCR-VL에서 1~3장 늘지만 시간이 2배가 됩니다. GLM-OCR에서는 정답도 줄고 시간도 늡니다.
- Vision 좌표로 자르면 영역 찾기가 Vision 호출에 포함되므로 VLM 시간만 더해집니다(GLM-OCR 중앙값 12.1초, PaddleOCR-VL 7.7초, Vision 호출 시간 제외). 다만 Vision을 호출하는 경로라 무료 대체재는 아닙니다.

**PaddleOCR 검출만의 시간:** 인식을 빼도 시간이 거의 줄지 않습니다. 50장 중앙값 17.0초(9~32초), 10초 이내 2장입니다. 2단계의 DJ 원본 읽기(검출+인식)는 중앙값 18.0초입니다. 실행 시점이 달라 바로 빼서 비교할 수는 없지만, PaddleOCR 시간은 대부분 검출에 드는 것으로 보입니다.

자른 결과를 파서가 성공으로 판정하면 쓰고, 아니면 전체 사진을 읽는 순서형 규칙입니다. PaddleOCR 시간은 빠져 있습니다.

## 4. 관찰

### 4.1 자르면 왜 시간이 줄어드는가
출력할 글자가 줄어들기 때문으로 보입니다. 시간의 대부분이 글자 출력에 드는데(`VLM_OCR_시간단축_실험결과_20261028.md`), 소재 영역은 토큰이 절반 이하로 줄고 시간도 함께 줍니다. 글자를 모두 포함하는 글자 상자 전체 영역은 토큰도 시간도 그대로입니다.

### 4.2 자르면 왜 정확도가 오르지 않는가
잘린 뒤 틀린 사진을 직접 보면, 영역이 잘못된 경우보다 같은 글자를 다르게 읽은 경우가 많았습니다.

- GLM-OCR에서 틀리게 된 4장은 영역 종류와 상관없이 같은 사진입니다. Vision 좌표 결과를 보면 소재명 오독 2장, 비율 숫자 오독 1장, 파서가 줄 나뉨에 걸린 사진 1장입니다.
- PaddleOCR-VL이 소재 영역에서 틀리게 된 2장도 소재명을 빠뜨리거나 잘못 읽었습니다(Vision 좌표 결과 기준).
- 맞게 된 사진과 틀리게 된 사진이 함께 나타나, 사진 수가 적은 DJ에서는 우연한 흔들림과 구분하기 어렵습니다. 이 분류는 표본을 본 것이며 전체 비율이 아닙니다.

### 4.3 기울기 보정
옆으로 누운 라벨 1장은 두 모델 모두 보정으로 다시 맞았습니다. 정답은 0~2장 늘고 틀린 성공은 없었습니다. 다시 읽은 사진이 16장뿐이라 효과 크기는 아직 판단하기 어렵지만, 줄어든 사진이 없어 후보로 유지합니다.

### 4.4 무료 경로에서 영역을 찾는 방법
서비스 영역 찾기는 글자 내용을 쓰므로 PaddleOCR이 잘못 읽으면 실패합니다(12장). 글자 상자 전체 영역은 48장 모두 만들 수 있지만 3.2처럼 효과가 없습니다. 검출 시간이 줄지 않으므로, 빠른 무료 경로에는 더 가벼운 검출 모델이 필요합니다. 이 저장소에는 `PP-OCRv5_server_det`만 있고, 가벼운 모델은 시험하지 않았습니다.

### 4.5 QA에서 다시 볼 이유
GLM-OCR을 예로 들면, 전체 사진을 50만 화소로 줄일 때 DJ(약 195만 화소)는 가로세로가 약 0.5배, QA(약 1,220만 화소)는 약 0.2배가 됩니다. QA는 축소 손실이 훨씬 커서 자르기의 정확도 효과가 DJ보다 클 수 있습니다. 아직 측정하지 않은 가설입니다.

## 5. 보고서에 쓸 점

1. 조성 영역만 잘라 읽으면 출력 토큰이 절반 이하로 줄고 VLM 읽기 시간도 줄지만, DJ 정확도는 뚜렷이 오르지 않습니다.
2. 무료 엔진만으로 자르려면 PaddleOCR을 먼저 돌려야 해서, 노트북 CPU에서는 전체 사진을 바로 읽는 것보다 느립니다.
3. 자르기와 순서형 결합까지 써도 DJ 최고 27/48로 Vision 원본 글자 36/48, 서비스 전체 경로 44/48에 못 미칩니다.
4. Vision 서비스 경로가 실패한 DJ 4장은 어떤 설정도 보완하지 못했습니다.
5. 모든 조합에서 틀린 성공은 0건이었습니다.

## 6. 한계

- DJ는 설정 조정에 쓴 사진이고 수가 적어 2~3장 차이는 흔들림일 수 있습니다. 같은 옷을 다시 찍은 사진도 섞여 있습니다.
- DJ는 카카오톡 전송본이라 원본보다 해상도가 낮습니다. 자르기의 이득이 가장 작게 나타나는 조건일 수 있습니다(4.5).
- 전체 사진 시간은 10-28, 자른 사진 시간은 11-03에 쟀습니다. 3.3은 서로 다른 날의 측정값을 더한 값입니다.
- **전원 상태가 다릅니다(4단계에서 확인).** 자른 사진과 PaddleOCR 검출은 전원 연결 상태이고, 전체 사진은 GLM-OCR이 배터리 + 전원 연결, PaddleOCR-VL이 배터리입니다. 같은 사진 10장을 전원 연결로 다시 재면 전체 사진 시간이 GLM-OCR 약 1.2배, PaddleOCR-VL 약 1.5배 짧습니다. 그래서 3.2의 시간 단축 폭은 과장됐을 수 있고, 3.3의 전체 사진 경로는 더 빠를 수 있습니다. 정확도는 영향이 없습니다(`VLM_OCR_프롬프트_실험결과_20261103.md` 3.4).
- 소재 영역 찾기는 서비스처럼 여러 후보의 좌표를 모으지 않고 원본 후보의 좌표만 썼습니다. 소재 영역 코드는 Vision 출력에 맞춰 개발됐습니다.
- 글자 상자 전체 영역은 저장된 PaddleOCR 단어 좌표로 만든 값입니다. 작아서 건너뛴 상자가 빠지므로, 검출만 돌린 실제 결과와 약간 다를 수 있습니다.
- 서비스 코드는 `c49205c` 기준입니다. 최신 `fc3316e`의 영역 코드로는 만들지 않았습니다.
- 시간은 GPU 없는 노트북 CPU 기준입니다.
