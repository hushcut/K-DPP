### 4.1 README 수치 재현

`15_stage5_compare.py`가 기존 결과 파일을 덮어쓰므로 **먼저 복사해 둡니다.** 이 스크립트는 `ksw/paddleocr`에만 있습니다.

```powershell
cd C:\kdpp_ocr_exp
$env:PYTHONIOENCODING="utf-8"
Copy-Item results\stage5_compare.json results\stage5_compare_20261025_backup.json
.\venv\Scripts\python.exe scripts\15_stage5_compare.py
```

맞춰 볼 값은 검증 365줄 정확 일치 57.5% → 75.9%, 띄어쓰기 무시 69.9% → 79.2%, CER 11.2% → 3.9%, 소재 관련 90줄 65.6% → 80.0%, 새로 틀린 18줄입니다.

### 4.2 평가 가능한 사진 수 확인

검증 사진은 36장이지만, **조성 정답표가 있는 사진만 채점할 수 있어 더 적을 수 있습니다.** QA 정답표는 89장뿐이기 때문입니다. `garment_groups.json`의 검증 사진과 QA 89장, DJ 48장 목록의 겹침을 먼저 셉니다. 10장 안팎으로 적으면 조성 비교는 사진별 관찰로만 기록합니다.

### 4.3 기본 모델과 학습 모델 비교

`20_read_batch.py`는 인식 모델 경로가 고정돼 있어 **`--rec-model-dir` 옵션을 추가해야 합니다(아직 없음).** 속도가 아니라 글자를 비교하는 단계이므로 기존과 같은 Paddle CPU 설정을 씁니다. 사진당 약 14초입니다.

```powershell
cd C:\K-DPP-OCR\experiments
$env:PYTHONIOENCODING='utf-8'
paddleocr\venv\Scripts\python.exe -X utf8 paddleocr\scripts\20_read_batch.py --photos <사진 폴더> --input-manifest <검증 목록> --exif-transpose --output paddleocr\results\<새 폴더_base>
paddleocr\venv\Scripts\python.exe -X utf8 paddleocr\scripts\20_read_batch.py --photos <사진 폴더> --input-manifest <검증 목록> --exif-transpose --rec-model-dir paddleocr\output\stage5_rec_infer_best --output paddleocr\results\<새 폴더_trained>
```

채점은 서비스 가상환경에서 `vlm_ocr/scripts/evaluate_batch.py`로 합니다. `--run base=<폴더> --run trained=<폴더>`로 넘기며, 부분 목록으로 동작하는지 먼저 확인합니다. 명령 형식은 `experiments/vlm_ocr/VLM_OCR_QA확인_결과_20261104.md` 7절을 따릅니다.

### 4.4 라벨과 정답표 확인

- **새로 틀린 18줄:** `stage5_compare.json`의 `changed.broken`입니다. 승우는 `12_005`, `47_020` 등 일부 라벨이 의심스럽다고 적었습니다. 고치면 수치도 다시 계산합니다.
- **정답표 의심 사진:** 승우가 표시한 6장 중 QA003, QA041, QA077이 QA 89장에 들어 있습니다. 사진을 함께 봅니다. 현재 채점은 다음과 같아 **Vision과 무료 최고 설정의 격차에는 영향이 없습니다.** 정답표가 바뀌면 절대 수치만 달라질 수 있습니다.

| 사진 | Vision 서비스 | Vision 원본 글자 | PaddleOCR-VL 표 인식 + 자름 |

| QA041 | 실패 | 실패 | 실패 |

세 장 모두 영역을 찾지 못한 사진이라, 무료 최고 설정은 표 인식 전체 사진 결과로 채점됐습니다.

### 4.5 무료 최고 경로 영향 (여유 있을 때)

학습 모델이 PaddleOCR 글자를 바꾸면 영역을 찾는 사진이 달라질 수 있습니다. 현재 QA는 89장 중 62장을 찾습니다. `service_paddle_run.py`로 새 OCR 캐시를 만들고 `make_region_crops.py`, `run_images.py`, `region_eval.py` 순서로 돌립니다. `21_ocr_worker.py`도 인식 모델 경로 확인이 필요합니다.

### 4.6 새 사진 (선택)

학습 모델의 독립 성능은 개발에 쓰지 않은 **새 옷 20~30벌**로만 말할 수 있습니다. 주말에 다 못 하면 계획만 정합니다.

- 같은 옷의 다른 사진을 학습용과 평가용에 나눠 넣지 않습니다. 정답은 사진에 적힌 그대로 적습니다.
- Vision 비교에는 새 호출이 필요합니다. 30장이면 약 77단위로 월 무료 한도(1,000단위) 안이지만, **호출 전에 이번 달 사용량을 보고 요한이 승인합니다.**

### 7.1 시간 (Core Ultra 7 155H 노트북, 전원 연결)

| 사진당 전체 경로, 영역 찾은 62장 | 중앙값 | 최대 | 10초 안 | 25초 안 |
|---|---:|---:|---:|---:|
| 기존 Paddle CPU + VL CPU | 26.4초 | 41.5초 | 0장 | 24장 |
| OpenVINO CPU + VL CPU | 14.7초 | 29.8초 | 12장 | 60장 |
| OpenVINO CPU + VL 내장 그래픽 | 9.8초 | 18.4초 | 32장 | 62장 |
| 검출 내장 그래픽 + VL 내장 그래픽 | 9.1초 | 17.6초 | 33장 | 62장 |
| 참고: Vision 서비스(89장) | 3.3초 | 6.5초 | 89장 | 89장 |

- 89장 전체(VL 내장 그래픽, 검출 내장 그래픽)는 중앙값 7.3초, 10초 안 56장, 25초 안 88장입니다. 남은 1장 QA077은 1,024토큰 상한까지 출력해 208초가 걸렸습니다.
- PaddleOCR 단계만 보면 89장 중앙값이 13.7초 → 1.5초(OpenVINO CPU) → 0.8초(검출 내장 그래픽)입니다. 1,352줄 모두 글자가 같고 좌표 차이는 0.0px입니다.
- PaddleOCR-VL 글자도 89장 모두 CPU 결과와 같아 QA 42/89는 유지됩니다(다시 채점하지 않음).
- 따로 잰 값을 더했고, 영역 찾기·기울기 보정·모델 불러오기는 뺐습니다. DJ는 재지 않았습니다.
- OpenVINO GPU 기본 정밀도 f16은 결과가 망가지므로 f32를 지정해야 합니다. 인식까지 GPU에 올리면 오히려 느립니다.
- **기존 문서와 달라진 점:** `experiments/vlm_ocr/VLM_OCR_QA확인_결과_20261104.md`의 "26.4초, 25초 제한 24/62"는 엔진 설정의 영향이 컸습니다. 보고서에 그대로 인용하지 않습니다.

### 7.3 비용 (현재 가격, 2026-11-04 확인)

- **Vision:** 월 1,000단위 무료, 이후 1,000단위당 $1.50입니다. 사진당 2.55회(QA) 호출이면 $0.0038입니다. 월 1만 장 $36.75, 10만 장 $381입니다.
- **상시 서버 1대(서울, 온디맨드, 제3자 집계 가격):** CPU `c7i.2xlarge` 월 $294(손익분기 약 77,300장), GPU `g4dn.xlarge` 월 $472(약 123,900장)입니다.
- **가동률:** 노트북 속도(평균 15.2초)를 빌려 계산하면, CPU 서버가 앞서려면 24시간 평균 가동률 45% 이상이 필요합니다. 서버 속도와 동시 요청은 재지 않았습니다.
- **실패 비용:** 무료 경로의 서버비를 0으로 쳐도 137장 기준 실패가 8.8~13.9% 많아, 실패 1건 손실이 $0.03~0.04를 넘으면 Vision이 이득입니다.

### 7.4 현재 결론 초안

Vision을 유지합니다. 근거는 작아진 사진에서의 안정성(DJ 36~44장 대 25장), 낮은 운영 부담, 예상 사용량에서의 비용입니다. QA 정확도와 처리 시간은 결정적 근거가 아닙니다. 월 수만 장 이상으로 늘거나 사진을 외부로 보낼 수 없게 되면 다시 검토합니다. **주말 결과에 따라 달라질 수 있고, 실제 예상 월 스캔 수도 아직 정해지지 않았습니다.**
