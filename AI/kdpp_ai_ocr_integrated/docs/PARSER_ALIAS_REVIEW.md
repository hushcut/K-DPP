# 일본어·중국어 소재 파서 보강 결과

## 작업 범위

2026-09-10 기준, `51f07a5`의 기존 소재 파서와 수정본을 동일한 합성 라벨
파일럿 정답 문자열로 비교했다. 이미지 OCR이나 Google Vision 학습을 수행한
결과가 아니다. 실제 QA 사진 163장과 기존 합성 이미지·정답표는 변경하지 않았다.

## 변경 내용

- 일본어 소재 별칭: 스판덱스, 비스코스, 캐시미어, 모달, 리오셀.
- 중국어 소재 별칭: 나일론, 레이온, 비스코스, 아크릴, 실크, 캐시미어, 모달, 리오셀.
- 일본어 `表地`(겉감), `リブ`(리브), 중국어 `螺纹`(리브) 구분.
- 띄어쓰기 없이 붙은 부위 이름과 소재명을 분리하고, 안감이 먼저 나와도 겉감을 선택.
- 유니코드 NFKC 정규화로 전각 숫자·문자와 반각 가타카나 처리.
- 모조/스타일 표현을 실제 소재로 확정하지 않도록 제한하고, 비율이 부위명보다 앞선 경우도 보존.
- API 호출 없이 반복 가능한 정답 문자열 전용 평가 CLI 추가.
- 합성 생성기의 중국어 아크릴 오타 수정. 생성 설정 버전은 `1.0.1`로 갱신.

## 동일 원본으로 비교한 결과

데이터는 기본 라벨 **20종 × 시각적 변형 4개 = 80장**이다. 같은 기본 라벨의
네 변형은 동일한 정답 문자열을 사용하므로 독립적인 문구 80개로 해석하면 안 된다.
평가기는 각 기본 문구를 한 번 검사하고 이미지 행과 원본 그룹 지표를 함께 기록한다.

| 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| 소재·혼용률 완전 일치 (`parse_label`) | 60/80 (75%) | 72/80 (90%) |
| 소재·혼용률 완전 일치 (`parse_materials`) | 60/80 (75%) | 72/80 (90%) |
| 기본 라벨 단위 소재·혼용률 일치 | 15/20 | 18/20 |
| 대표 부위 선택 일치 | 68/80 (85%) | 80/80 (100%) |
| 한글 소재·혼용률 일치 | 20/20 | 20/20 |
| 영어 소재·혼용률 일치 | 20/20 | 20/20 |
| 일본어 소재·혼용률 일치 | 8/20 | 20/20 |
| 중국어 소재·혼용률 일치 | 12/20 | 12/20 |

기존에 소재·혼용률이 맞던 60개 행은 모두 유지되었다. 중국어는 기존 파일럿의
실패 두 원본에 생성 오류가 있어 전체 점수가 그대로다. 올바른 중국어 소재명을
사용하는 별도 혼방 문구, 부위 분리, 전각 문자 회귀 검사로 추가 별칭을 검증했다.
이 파일럿에 맞춘 개선 결과만으로 실제 촬영 이미지의 일반화 성능을 판단할 수 없다.

## 남은 두 원본의 문제

1. `SYN_SOURCE_0004` (4장): 아크릴 95%, 레이온 5%의 아크릴 표기가
   `腈纶` 대신 `腨纶`으로 생성되었다. 잘못된 철자를 정상 별칭으로 등록하지 않았다.
2. `SYN_SOURCE_0020` (4장): 동일한 아크릴 오타 외에도 정답은 `spandex`지만
   표시된 `氨纶`은 생성기에서 `spandex`와 `polyurethane` 양쪽에 사용된다.
   기존 파서는 `氨纶 → polyurethane`이다. 기존 API 결과를 갑자기 바꾸지 않도록
   이번 변경에서 이 매핑을 유지했고, 평가 정답도 재매핑하지 않았다.

이 8개 행을 제외하거나 원본 정답을 바꾸어 점수를 높이지 않았다.
알 수 없는 소재가 포함될 때 기존 파서의 비율 보정이 남은 소재를 100%로 만들 수
있으므로, 잔여 실패 결과를 정상 혼용률로 사용하면 안 된다. 이 동작 역시 평가
JSON에 실제 예측값으로 남는다.

표기 확인 근거: 중국 상무부는 아크릴을
[`腈纶`](https://www.mofcom.gov.cn/zcfb/zgdwjjmywg/art/2016/art_e99d9c49cf81478f932ae1621d5496a5.html)으로
표기하며, 중국 국가표준 플랫폼의
[`氨纶` 관련 문서](https://std.samr.gov.cn/gb/search/gbDetailed?id=5DDA8B9DA7C018DEE05397BE0A0A95A7)는
이를 영어 `elastane`과 대응시킨다. 프로젝트 내부의 두 소재 키를 어떻게 통일할지는
파서·생성기·백엔드 정답 기준을 함께 맞춰야 하는 별도 결정이다.

## 검증 및 재실행

AI 프로젝트 루트에서 실행한다. 평가 CLI는 Python 표준 라이브러리만 사용한다.
전체 테스트 중 생성기 테스트에는 Pillow가 필요하다.

```powershell
python -B -m unittest discover -s tests -v
python -B scripts/evaluate_synthetic_parser.py --manifest outputs/synthetic/synthetic_v1_pilot/manifest.csv --output outputs/synthetic/parser_alias_review/after.json
```

비교할 이전 코드가 별도 폴더에 있으면 같은 평가기에
`--parser-root <이전_AI_프로젝트_폴더>`를 전달한다.
각 JSON에는 파서 파일 해시, manifest 해시, 언어별 지표, 실패 원문과 예측을 남긴다.
평가 완료는 실패 사례가 있어도 종료 코드 0이고, manifest·설정 오류는 2이다.

검증 환경: Python 3.12.14, Pillow 12.3.0. 전체 unittest 21개 통과.
회귀 검사는 파일럿에 없는 혼용률과 소재 조합, 숫자 선행·열 배치, 부위 순서 반전,
부위·소재 붙여쓰기, 전각/반각 입력, 한글·영어 기존 동작을 포함한다.
