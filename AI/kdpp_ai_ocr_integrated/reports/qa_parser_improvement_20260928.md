## 부작용과 방어

- 최초 비율 선행 규칙은 QA031의 별도 `100%`를 뒤의 면 95% 행에 재사용하여 이전에 막은 오답을 되살렸다. 소재 뒤에 자기 비율이 있으면 앞 비율과 연결하지 않도록 막고 회귀 테스트를 추가했다.
- 각 유형 수정 뒤 저장 OCR 89건을 다시 점수화했다. 별칭 수정에서는 목표 5건만, 비율 배치 보완 뒤에는 7건만, 최종 규칙에서는 목표 11건만 결과가 바뀌었다. QA031은 계속 안전 실패다.
- 원문 OCR이나 사진, 브랜드·개인정보를 이 보고서나 테스트 fixture에 넣지 않았다. 추가 회귀 테스트는 축약한 조성 문자열을 쓴다.

## 검증

- 새 회귀 검사로 처음 4개의 성공 조건이 실패하는 것을 재현했다. 파서 안전 조건도 함께 추가했다.
- 파서·오답 방어 테스트 **134개**, 전체 AI·QA **310개**, Ruff 검사 통과.
- 전체 테스트에서는 `tests/test_backend_ai_wiring.py`를 제외했다. 이 검사는 백엔드 import 중 로컬 SQLite 스키마를 변경할 수 있다.
- 실제 이미지 89건을 `scripts.run_qa_batch --offline`으로 재실행: **70/89(78.7%)**, 기준 59/89(66.3%)보다 11건 증가. 파서 성공 70건, 실패 19건.
- 비교 대상 89건 중 상태·소재·대표 부위가 바뀐 것은 목표 11건뿐이며 모두 실패→정답으로 바뀌었다. 기존 정답 59건과 QA031 안전 실패를 유지했다. 성공으로 나온 오답은 이 정답지 기준 **0/70건**이다.
- 캐시 hit/miss/write **126/0/0**, 외부 API 사용 이미지 **0**, 예외 **0**. 실패 코드는 `composition_not_found` 18건과 `incomplete_part_composition` 1건이다.
- 캐시·정답지·사진·DB의 검사 전후 SHA-256이 동일하다. 결과는 `.test-artifacts/qa-parser-improve-20260928/results.csv` 및 `results.summary.json`에 따로 저장했다.

## 남은 19건과 OCR 개선 후보

- 앞선 감사에서 OCR 근거 부족으로 분류한 15건, 복합 2건, 정정된 정답지 기준으로 다시 봐야 할 QA001, 의도적으로 거절한 QA031이 남는다. 이 분류는 저장된 OCR 증거에 근거하며 Vision 자체의 오류율을 뜻하지 않는다.
- QA060은 이미 저장된 반사 보정 후보에서 면 100%가 확인됐다. 기본 처리에 세 번째 OCR 호출을 추가할지는 정확도·지연·비용을 함께 측정한 뒤 결정한다.
- 소재명이 거의 사라진 QA027·040·042·073·077 등은 라벨 영역 자르기와 방향·확대 전처리의 우선 검토 대상이다. 비율 숫자가 손상된 QA015·037·041·055 등은 숫자 읽기 개선 대상으로 분리한다. 현재 캐시만으로는 새 전처리의 효과를 측정할 수 없다.
- QA001·046·083·097 같은 부위 경계 사례는 사진의 겉감과 하위 부위를 다시 대조하면서 OCR 줄 배치와 파서 선택을 함께 점검해야 한다. 정답을 OCR에 보충하거나 합계가 불완전한 값을 임의로 확정하지 않는다.

코드 변경의 성과는 저장된 OCR 후보·정정된 정답지에 한정된다. 새로운 Vision 실호출 결과나 실제 서비스 인식률로 해석하지 않는다. OCR 개선 후보의 실효성 확인과 기존 목록 4~9번은 별도 작업이다.
