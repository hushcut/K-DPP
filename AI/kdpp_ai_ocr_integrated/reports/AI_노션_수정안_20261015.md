### AI 파트 프로젝트 현황

갱신일: 2026-10-15. 기준은 `ai-integration`의 부모 `da62998` 이후 AI·공통 보안 보완이다. 로컬 검사 결과와 게시 커밋의 GitHub CI 결과는 구분해 기록한다.

#### 해결하려는 문제와 사용자

의류의 탄소배출량을 소재 기준으로 계산하려면 라벨의 소재명·혼용률뿐 아니라 **어느 부위의 조성인지** 알아야 한다. 사용자가 작고 흐리거나 여러 언어로 적힌 라벨을 직접 읽어 입력할 때, 소재 누락·비율 오독·겉감과 안감의 혼동이 생길 수 있다. 잘못된 결과가 성공으로 전달되면 탄소 계산의 입력도 잘못된다.

초기 대상은 의류 라벨을 촬영해 소재 정보를 확인하고 탄소 추정값을 살펴보려는 앱 사용자다. AI의 역할은 촬영된 라벨의 근거로 소재와 혼용률을 구조화하고, 계산에 사용할 조성이 불완전하면 이를 성공으로 확정하지 않는 것이다. 실제 사용자 편의성과 효과는 앱 연동·사용자 검증이 추가로 필요하다.

환경과 세탁 관련 활용이라는 장기 목표에 맞춰 현재 대표 조성은 **겉감을 우선**한다. 세탁 단계의 환경 효과를 실제로 산정하거나 AI로 수명을 예측하는 기능은 현재 완료 범위에 포함하지 않는다.

#### 현재 AI 처리 흐름

```text
라벨 사진
  → Google Vision OCR로 글자·단어 좌표 수집
  → 원문·배치·필요한 전처리/확대 후보 비교
  → 소재·혼용률·부위의 근거 및 합계 검증
  → 대표 조성 성공 / 미확정 실패 / 내부 확인·재촬영 근거
  → 백엔드가 앱 응답에 연결
```

문자 추출은 Google Vision을 사용한다. AI 파트에서 직접 구현·보완한 부분은 다국어 소재 표준화, 좌표에 따른 행 연결, 같은 영역의 재인식 근거 검증, 겉감 우선 선택, 불완전·충돌 조성 거절, 재현 가능한 QA다. 직접 학습한 OCR 모델의 정확도로 소개하지 않는다.

탄소 계산·이력은 백엔드의 별도 `/api/carbon/calculate`가 담당한다. `/api/scan`의 OCR 결과와 계산·저장 완료를 같은 상태로 취급하지 않는다.

#### 핵심 판단 원칙

- 겉감·겉감2를 먼저 평가한다. 관측된 겉감이 미확정이면 완성된 안감이나 배색으로 대신 성공하지 않는다.
- 예를 들어 ‘겉감 면 95%, 나머지 불명 / 안감 면 100%’는 실패다. 최상위 계산용 소재를 비운다.
- 정상 겉감은 다른 부위의 오류 때문에 버리지 않는다. 겉감 근거가 없고 다른 명시 부위가 확인되면 그 부위를 반환할 수 있다.
- `generic` 성공은 조성을 읽었지만 부위를 모르는 상태다. OCR에 겉감 표기가 없다고 실제 사진에도 겉감이 없다고 단정하지 않는다.
- 소재명·양수 비율·완전한 합계·같은 부위의 근거를 확인한다. 누락 비율을 추정하거나 불완전한 조성을 100%로 늘리지 않는다.
- 다른 성공 사진으로 실패 사진을 대신 채우지 않는다. 같은 사진의 재인식도 원래 위치와 소재·비율의 연결을 확인해야 인정한다.
- `high/medium/low`는 검증된 정답 확률이 아니다. 성공 결과도 부위와 계산 지원 여부를 함께 확인해야 한다.

### 1학기 소개

1학기에는 의류 케어라벨에서 소재명과 혼용률을 추출하는 초기 OCR·파싱 흐름을 구축하고, 잘라낸 세탁기호를 분류하는 ResNet18 실험을 진행했다. 다양한 언어·작은 글자·줄과 열의 배치가 결과에 영향을 준다는 점을 확인했다. 이 시기의 결과는 초기 구현과 한계를 확인한 기록이며 현재 앱 전체의 성능을 뜻하지 않는다.

### 세탁기호 실험 범위

초기 ResNet18 학습에서는 학습 정확도 약 98%와 검증 정확도 약 31~37%의 차이가 나타났다. 학습 집합의 높은 수치만으로 실사용 성능이 충분하다고 판단할 수 없었다. 기호별 데이터 분포, 원본 중복과 분할, 실제 사진 조건을 확인해야 한다는 후속 과제를 얻었다. 이 실험은 잘라낸 단일 기호 분류이며, 라벨 전체에서 기호 위치를 찾는 기능이나 현재 제품의 세탁 안내 정확도로 사용하지 않는다.

### 초기 OCR 화면 설명

위 이미지는 초기 응답 형식을 남긴 개발 기록이다. 첫 화면의 ‘면 35%인데 성공’처럼 일부 조성만 읽고 성공한 예는 현재의 합계·누락 검증 기준에 맞는 정상 성공 예시로 사용할 수 없다. 현재 설명에서는 소재와 비율이 완성되지 않으면 실패해야 한다는 개선 동기를 보여주는 사례로 표시한다. 이 스크린샷만으로 원본 사진을 최신 코드에서 다시 검증한 것으로 주장하지 않는다.

당시 응답의 `expected_life_months: 36` 표기도 학습 기반 수명 추정 성능을 증명하지 않는다. 현재 완료 기능에 AI 수명 예측을 포함하지 않는다. 원시 OCR 전체 문자열 대신 필요한 소재 결과와 실패 이유만 발표 자료에 사용한다.

### 과거 QA 표의 해석

1학기 문서의 71/89→78/89→83/89는 당시 정답지와 구현 조건으로 정리한 과거 기록이다. 코드·정답지 버전·전처리 옵션·채점 범위가 같은 재현 자료를 연결하기 전에는 최신 정확도 표의 기준값으로 사용하지 않는다. 현재의 동재 사진·변형 이미지 평가와 데이터 및 시점이 달라, 83/89와 44/48 또는 185/200을 직접적인 전후 개선량으로 빼거나 합산하지 않는다.

### 2학기로 연결한 과제

초기 구현을 통해 글자를 추출하는 것과 계산에 사용할 조성을 확정하는 것이 다르다는 점을 확인했다. 2학기에는 누락된 비율의 임의 정규화, 소재·비율의 잘못된 연결, 겉감과 안감의 혼동, 틀린 조성을 성공으로 반환하는 문제를 우선 점검했다. 과거 실패를 회귀 사례로 남기고, 현재 결과는 코드·자료·옵션과 함께 별도로 기록하는 방향으로 발전시켰다.

### 2026-10-15 최신 개선: 겉감 우선과 근거 기반 재인식

환경 관련 계산에서 대표 조성이 다른 부위로 바뀌면 결과의 의미가 달라진다. 이에 관측된 겉감이 불완전할 때 안감의 완성 조성으로 대체하던 동작을 거절하도록 정정했다. ‘겉감 면 95%+미확실, 안감 면 100%’는 자동 실패로 남기고 계산용 소재를 반환하지 않는다.

인식 개선에서도 사진 번호나 정답 비율을 코드에 넣지 않았다. 같은 사진·같은 부위·같은 행의 근거를 확인하고, 확대 결과가 원문의 다른 영역 오류를 덮지 못하게 했다. 회전 라벨의 짧은 글자 상자가 기울기 판정 경계에서 분리되던 경우에는 기존 각도 기준을 유지하면서 최대 1픽셀의 경계 오차만 보완했다. 기존 구역이나 모호함이 확인된 경우에는 이 보완으로 결과를 바꾸지 않는다.

이 수정으로 저장 OCR의 DJ038 일본어 회전이 겉감 조성으로 복구됐고 변형 자료의 소재·부위 일치는 184→185/200이 됐다. 같은 실사진 50장의 두 OCR 기록은 각각 소재 44/48·소재와 정답 대표 부위 43/48을 유지했다. 새 Vision 호출은 하지 않았다.

### 이번 최종 평가에서 확인한 중요한 한계

실사진 소재 성공 44건 중 32건은 `generic`이다. 겉감 정답 항목 14건 중 겉감 조성까지 맞힌 것은 11건이며, DJ015는 소재만 맞고 부위를 모른다. 이 때문에 소재 일치율만 높아진 것으로 제품 전체가 겉감 기반 계산을 안전하게 수행한다고 설명하지 않는다.

### 코드 검증과 유지보수

부위 우선순위는 공통 정책으로 관리하고 추가 후보의 실행·예외·시간 처리를 재사용한다. 좌표 검증을 분리하고 배포 런타임 포함 여부를 검사했다. 최신 수정본의 전체 회귀 4,581건·격리 DB 연동 14건·Python 151개 문법·Ruff·의존성 검사가 통과했다. 보안 검사 22개도 별도로 통과했다. 관련 816개는 전체 회귀에 포함하며 부모 `da62998`의 CI와 새 게시 커밋 CI는 구분한다.

AI 영역의 실제 환경 설정·일반 자격증명 파일명·개인키 제외도 보강했다. 경로 193개와 기존 추적 파일 172개를 검사했으며 정상 소스는 새로 제외하지 않았다. 공통 Gitleaks 검사·로컬 커밋/푸시 전 훅을 설치하고 두 브랜치 로컬 이력을 검사했다. 보안 CI 코드도 구성했다. 게시 커밋의 GitHub 실행 결과 확인·`kyh/ai` 코드 공유·새 PC 설치·관리자 보호 설정은 별도다. 알려지지 않은 모든 키 형식까지 완전 탐지한다고 보장하지 않는다.

### 제품 연결에서 남은 사항

AI 내부의 부위 미확정·재촬영 근거를 앱에 표시하는 연결, 계산 미지원 소재의 저장 정책, 팀이 승인한 탄소계수 근거가 남아 있다. DJ009의 사용자 확인 연결은 보류 중이다. 확인 후보가 준비돼 있다는 이유로 앱에서 사용자가 확인할 수 있다고 설명하지 않는다.

세탁기호는 단일 기호 분류 실험이며 전체 라벨 검출과 제품 기본 연결은 없다. 현재 목표는 소재·겉감·실패 처리의 근거를 명확히 하고, 담당자 연동과 검증 범위를 실제 완료 상태에 맞춰 남기는 것이다.

## 5. 노션 반영 전후 확인

- 현황 페이지의 작업 브랜치는 `ai-integration`으로 갱신한다. `kyh/ai`는 과거 작업 기록 또는 별도 개인 브랜치로 구분한다.
- ‘실사진 수치 없음’, ‘CI 미구성’은 현황 페이지에서 현재 상태로 사용하지 않는다. 저장 실사진 결과와 로컬 전체 회귀 4,581건·연동 14건·보안 22개 결과가 있다. 게시 커밋의 GitHub CI 결과는 별도로 연결한다.
- 83/89·73/89·15/16·44/48·185/200에는 시점·자료·옵션·분모를 붙인다. 서로 다른 검사를 하나의 성능 변화 그래프로 연결하지 않는다.
- 44/48에는 부위 미확정 32건과 겉감 11/14를 함께 표시한다. `generic`을 겉감으로 표시하지 않는다.
- 키·인증 JSON·실사진·정답표·OCR 전체 원문·개인 로컬 경로·내부 예외를 페이지에 복사하지 않는다.
- 게시한 정확한 커밋·CI 링크와 검사 범위를 확인해 갱신한다. 원고 작성·로컬 검사와 원격 CI 완료를 구분한다.
- Notion 연결과 대상 페이지 확인 후 실제 반영 여부를 별도로 기록한다. 현재 상태는 **원고 완성·노션 미반영**이다.
