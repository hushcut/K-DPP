준원님, R1은 계산 API가 입력을 거절해도 앱이 저장을 계속하는 문제입니다. R4는 AI의 공개 안내 코드가 이미 반영됐는데 백엔드 테스트가 이전의 빈 경고 배열을 기대해 CI 1개가 실패하는 상황입니다. 아래 두 건을 담당 브랜치에서 반영하고 R4가 포함된 상태로 통합 검증 부탁드립니다.

## 1. R1 — 계산 400/422 거절 시 앱 저장 중단

### 현재 문제와 수정 위치

`POST /api/carbon/calculate`가 미지원 소재·잘못된 비율 등을 400/422로 거절하면, 프론트는 이를 `CarbonApiErrorType.badRequest`로 분류합니다. 하지만 `_submitClothes()`는 인증 오류 외의 계산 오류에 안내 문구만 설정하고 `addClothesForOwner()`로 계속 진행합니다. 그 결과 서버 계산이 거절된 입력도 로컬 추정값으로 옷장에 저장될 수 있습니다.

예를 들어 미지원 소재의 계산이 `MATERIAL_NOT_FOUND`로 거절돼도 임시 탄소값과 “저장했어요” 문구로 처리될 수 있습니다. 이는 기준 커밋의 소스에서 확인한 흐름이며 이번에 운영 서버로 새 재현을 한 것은 아닙니다.

서버 요청 전에 로컬 초안을 만들며, 미등록 소재의 로컬 기본 배출계수는 10.0입니다. 문제는 입력 거절 뒤에도 그 초안을 저장하는 분기이므로 기본 계수 변경으로 해결하지 않습니다.

| 위치 | 확인·수정할 내용 |
| --- | --- |
| [scan_save_actions.dart:122](../../../FRONTEND/lib/scan/scan_save_actions.dart#L122) | 계산 오류 처리에 `badRequest` 저장 중단 분기 추가 |
| [scan_save_actions.dart:140](../../../FRONTEND/lib/scan/scan_save_actions.dart#L140) | 입력 거절 이후 옷장 추가·저장 완료 콜백·리포트 전환으로 진행하지 않도록 처리 |
| [scan_save_actions.dart:158](../../../FRONTEND/lib/scan/scan_save_actions.dart#L158) | 조기 종료 경로에서도 `_isSaving` 해제·재시도 가능 상태 복구 |

### 최소 수정 범위

1. **탄소 계산 API의 400/422 입력 거절**이면 저장을 중단합니다. 스캔 API의 422 소재 추출 실패와 구분합니다.
2. 소재·혼용률과 폼을 유지하고, 입력을 수정하거나 재촬영할 수 있게 합니다. 미지원 소재를 임의 치환하거나 계수를 추가하지 않습니다.
3. “소재와 혼용률을 확인해 주세요” 등 저장하지 않았다는 사실에 맞는 안내를 표시합니다.
4. 저장 버튼 로딩을 해제하고 수정 후 재시도할 수 있게 합니다.

**로딩 주의:** 현재 `_isSaving` 복구는 옷장 저장 구간의 `finally`에 있습니다. 계산 오류 처리에 `return`만 넣으면 해당 구간을 건너뛰어 버튼이 계속 잠길 수 있으므로 종료 처리를 함께 확인해야 합니다.

401 인증 만료·네트워크·시간 초과·서버 장애·비로그인 저장 정책은 별도입니다. 이번 수정은 명시적 입력 거절을 대상으로 하며 다른 오류의 저장 정책까지 일괄 변경하는 요청이 아닙니다.

### R1 확인 기준

| 모의 응답·상황 | 기대 결과 |
| --- | --- |
| 계산 400 `MATERIAL_NOT_FOUND` 또는 다른 입력 거절 | 옷장 추가·저장 완료 콜백 0회, 소재·비율 유지, 수정 안내 |
| 계산 422 입력 검증 거절 | 저장·리포트 전환 없음, 입력 유지, 로딩 해제 |
| 거절 후 수정·재시도 | 저장 버튼 사용 가능, 새 입력으로 재요청, 성공 시 1회 저장 |
| 정상 계산 200 | 서버 계산값·ID로 정상 저장, 중복 저장 없음 |
| 401·통신/서버 장애·비로그인 | 입력 거절과 구분하고 기존 합의된 정책 유지 |

기존 [scan_screen_test.dart:501](../../../FRONTEND/test/scan_screen_test.dart#L501)는 서버 오류의 임시 저장을 검사하므로 400/422 저장 중단의 전용 검사가 필요합니다. Flutter 3.41.5 / Dart 3.11.3 기준으로 관련 검사와 `flutter analyze`, `flutter test`를 확인해 주세요.

백엔드의 계산 거절·서버 이력 미저장 검증 완료는 10/19 담당자 회신 기준입니다. 앱 옷장의 저장 중단은 별도 확인해야 합니다. 기존 R1 단독 요청서의 수정 범위·로딩 주의·검증 기준은 이 통합 문서에 포함했습니다.

## 2. R4 — 공개 안내 코드에 맞춘 백엔드 테스트 수정

### 이미 반영된 AI 동작과 CI 결과

AI는 기존 `warnings: string[]`에 공개 부위·재촬영 코드를 추가했습니다. 소재·혼용률·성공/실패·부위 선택은 유지합니다. 부위 표기가 없는 성공 입력은 `composition_part:unidentified`로 안내하며, 이 코드는 소재 인식 실패를 뜻하지 않습니다.

기준 커밋의 CI는 다음과 같습니다. **AI 검사는 최종 통과했으며 전체 CI는 백엔드 검사 1개 때문에 실패 상태입니다.**

| 검사 | 결과 |
| --- | --- |
| AI OCR·파서·백엔드 연결 | 통과 |
| 프론트 분석·테스트 | 통과 |
| 배포 이미지 빌드·마이그레이션·앱 시작 | 통과 |
| 비밀정보 검사 | 통과 |
| 백엔드 pytest | 546개 중 545개 통과·1개 실패 |

### 실패 위치와 요청하는 수정

대상: [test_scan_ai_integration.py:64](../../../BACKEND/tests/test_scan_ai_integration.py#L64)의 `test_photo_scan_returns_materials_and_warnings_only`, 실패 단언은 73줄입니다.

검사 입력은 `COTTON 80% POLYESTER 20%`로 겉감·안감 표기가 없으므로 성공 결과의 부위는 미확정입니다. 따라서 다음과 같이 기대값을 갱신해 주세요.

```diff
-    assert body["warnings"] == []
+    assert body["warnings"] == ["composition_part:unidentified"]
```

기존의 HTTP 200·소재 비율·`ai_success`·내부 메타데이터 비노출·Vision 호출 횟수 단언은 유지합니다. 위 기대값은 이 검사 입력에 대한 것이며 모든 성공 결과에 같은 부위 코드를 강제하는 요청은 아닙니다. 전체 코드 표와 출력 조건은 [AI README의 R4 절](../README.md#공개-부위재촬영-안내-warnings-r4)을 기준으로 합니다.

백엔드 담당 환경의 테스트 DB 준비는 [BACKEND README](../../../BACKEND/README.md)를 따르고, BACKEND에서 해당 검사 파일과 전체 pytest를 확인해 주세요. 이 검사는 모의 OCR을 사용하므로 수정 검증을 위해 새 Vision 실호출을 할 필요는 없습니다.

**R4 전체 연동은 별도:** 이 테스트 수정만으로 앱의 부위·재촬영 안내 표시나 부위 미확정 확인/계산 정책이 완료되지는 않습니다. 해당 앱 연결과 정책은 후속 통합 범위이며 R5 후보 확인 기능은 계속 보류입니다.

## 3. 담당 반영·통합 순서와 완료 기준

1. 프론트 담당은 R1 저장 중단·안내·로딩·전용 검사를 반영합니다. R1은 R4 앱 표시 구현을 기다리지 않고 진행할 수 있습니다.
2. 백엔드 담당은 R4 공개 코드에 맞춘 위 테스트를 수정합니다. **기대값 수정은 R4 AI 코드가 포함된 상태에서 검증해야 합니다.** R4가 없는 브랜치에 기대값만 먼저 적용하면 응답과 다시 불일치할 수 있습니다.
3. 수정 커밋을 R4가 포함된 `ai-integration`에 통합하고, 프론트·백엔드·배포 이미지·AI·보안의 검사 5개가 모두 통과하는지 확인합니다.
4. 계산 거절 후 앱 옷장과 서버 이력에 새 결과가 생기지 않고, 입력 수정·재시도·정상 저장이 가능한지 확인합니다.
5. 반영 브랜치·정확한 커밋·관련 검사 결과·통합 CI 링크와 남은 앱 연동 항목을 공유해 주세요.
