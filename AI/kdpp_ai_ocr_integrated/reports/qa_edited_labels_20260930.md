# 글자 변경 이미지 전처리 재검사 — 2026-09-30

## 결과

사용자가 지정한 `AI로 글자 바꾼 이미지들`의 V1·V2 총 40개 PNG를 확인했다.
17개는 버전 사이의 SHA-256이 같아 실제로 서로 다른 이미지는 23장이다.
그중 조성이 일관된 16장은 현재 기본 전처리로 13장, 미세 회전 재시도를 추가하면
15장이 정답과 일치했다. 기존에 맞던 13장은 모두 유지됐다.

| 비교 범위 | 변경 전 | 미세 회전 추가 후 |
| --- | ---: | ---: |
| 조성이 일관된 고유 이미지 | 13/16 (81.3%) | 15/16 (93.8%) |
| 위 이미지의 중복 파일까지 포함 | 24/29 | 28/29 |
| 기존 실사진 회귀 집합, 반사·노이즈 완화 활성화 기준 | 73/89 | 73/89 |

정답표를 제공받지 않아, 이미지의 조성 문구를 직접 검수한 임시 정답을 사용했다.
소재 집합과 혼용률 ±3%p를 비교했으며 독립 평가 성능이나 문자 단위 정확도는 아니다.
나머지 고유 7장(파일 11개)은 서로 다른 조성이 함께 남거나 수정 전 표기가 남아 있어
일반 정확도 분모에서 제외했다. 제외 목록과 이유는 아래에 모두 기록한다.

## 코드와 사용 옵션

- `apps/text/ocr_image.py`에 `preprocess_rotated_image_bytes()`를 추가했다. -3도 회전 시 캔버스를 확장하고, 확장 후에도 기존 픽셀 수·최대 변 길이 제한을 지킨다. 대비·선명화 후 JPEG 품질 92로 출력한다.
- `apps/text/ocr_text.py`에 `enable_rotated`와 `KDPP_ENABLE_ROTATED_OCR`을 추가했다. 기본값은 꺼짐이다. 앞선 모든 후보가 실패했을 때만 실행하며 성공 결과는 교체하지 않는다.
- 반사·노이즈 완화가 켜져 있다면 그 뒤에 미세 회전을 실행한다. 셋을 모두 켜면 원본·기본 전처리를 포함해 최대 5개 후보가 된다. 기존 전체 시간 예산과 후보별 5초 설정을 사용한다.
- 파서·소재 사전·백엔드·프론트엔드·실행 중인 서버는 변경하지 않았다.

이 편집 이미지 집합에서는 기본+회전만으로 같은 15/16을 얻었다. 고유 23장을 캐시 없이
처리할 때 기본 40개, 기본+회전 47개의 후보가 필요하다. 반사·노이즈까지 모두 켜면
61개로 늘지만 이 집합에서 추가 정답은 없었다. 기존 실사진의 반사·노이즈 개선과는
다른 결과이므로 한 집합의 최적 설정을 모든 사진에 일반화하지 않는다.

회전 재시도를 사용하려면 AI를 실행할 프로세스의 환경에서 다음 옵션을 설정한다.

```powershell
$env:KDPP_ENABLE_ROTATED_OCR = "1"
```

이번 작업은 실행 중인 서버의 설정을 바꾸거나 서버를 재시작하지 않았다.

## 실행·검증 기록

- 시작 기준은 HEAD `6e7b12f`와 직전 작업의 미커밋 전처리 변경이다. 기존 변경을 보존했다.
- 새 Vision 요청은 101회: 기본·기존 추가 후보 비교 54회, 각도 비교 및 좌표 확인 10회, 실패 사진 회전 검증 21회, MPO 정규화 후 재검증 16회다. 직전 실사진 전처리 작업의 217회와 별도다.
- 첫 회전 실험 도구가 기존 실사진 16장의 MPO→JPEG 정규화 단계를 빠뜨려 제품 경로와 후보 바이트가 달랐다. 최종 오프라인 검사에서 캐시 누락으로 발견했다. 이 16개 정규화 전 응답은 최종 비교에서 제외하고 실제 `run_ocr_bytes()` 경로로 각 1회 다시 호출했다. 편집 PNG의 개선 결과는 영향을 받지 않았다.
- 최종 코드에서 편집 고유 23장과 기존 실사진 89장을 저장된 응답으로 재검증했다. 기존 실사진은 직전 실험의 응답과 이번 회전 응답을 함께 사용했으며 전체 89장을 새로 재호출한 것은 아니다.
- 최종 캐시 hit/miss/write는 **225/0/0**, 추가 API 호출은 0회다. 편집 원본 40개와 보호한 기존 캐시·정답지의 해시 보존도 확인했다.
- 기존 실사진 89장의 소재 결과와 정답 판정은 모두 동일하며 73/89를 유지했다. 회전 추가 요청 대상 16장에서도 새 오답·추가 정답은 없었다.
- 관련 OCR 테스트 71개, 백엔드 연결 제외 전체 AI·QA 테스트 **361개**, Ruff 통과.
- 새 회전 테스트 14개는 옵션 적용·기존 성공 보존·실행 순서·오류와 시간 예산·캔버스 확장·크기 제한을 검사한다.
- 원본 이미지·기존 캐시·정답지는 보존했다. DB 작업, 서버 시작·종료, 커밋·푸시는 하지 않았다.
