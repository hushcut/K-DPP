# K-DPP Safety Rules

## 서버와 백엔드 SQLite

- `BACKEND/database.py`는 import 시 `ensure_schema()`를 실행한다.
- `BACKEND/main.py` import도 `database.py`를 불러오므로 `BACKEND/k_dpp.db`를 생성하거나 스키마를 변경할 수 있다.
- 백엔드 서버 시작 시 startup 핸들러가 소재 기준 데이터를 추가·갱신한다.
- 코드 구조를 읽기 위해 백엔드를 import하거나 서버를 시작하지 않는다. 소스 파일을 직접 읽는다.
- 로컬 DB를 보존해야 하는 상황에서 백엔드 import가 포함된 테스트나 서버를 실행하기 전에는 영향과 백업 필요성을 사용자에게 알린다.
- `BACKEND/k_dpp.db`와 journal·WAL·SHM 파일을 삭제, 초기화, 교체하거나 커밋하지 않는다.

## Google Vision OCR

- `GOOGLE_APPLICATION_CREDENTIALS` 값과 서비스 계정 JSON의 절대 경로·내용을 출력하거나 문서에 기록하지 않는다.
- 단위 테스트와 `--offline` QA는 Google Vision 실호출 없이 수행한다.
- `scripts/run_qa_batch.py`를 `--offline` 없이 실행하거나 OCR 캐시를 갱신하면 외부 API 호출과 비용이 발생할 수 있으므로 사용자의 명시 요청 후 실행한다.
- `KDPP_ENABLE_REFLECTION_OCR=1`은 이미지당 추가 OCR 후보를 활성화하므로 실험 목적과 호출 비용을 확인한다.
- API 오류의 원시 예외, 자격증명 위치, 요청 원문 전체를 사용자 응답에 노출하지 않는다.

## 데이터, 모델과 생성물

- `AI/kdpp_ai_ocr_integrated/data/`: 로컬 심볼 데이터셋
- `AI/kdpp_ai_ocr_integrated/models/`: 로컬 모델 체크포인트
- `AI/kdpp_ai_ocr_integrated/outputs/`: OCR 캐시, QA·합성 평가 생성물
- `QA_DATASET/`: 로컬 실사진 QA 데이터와 결과
- 위 경로는 Git 추적 대상이 아니다. 삭제·이동·덮어쓰기 전에 정확한 대상을 확인한다.
- OCR 캐시와 결과에는 라벨 원문이 포함될 수 있으므로 채팅이나 커밋에 원문을 대량으로 복사하지 않는다.
- 심볼 학습과 평가는 장시간 연산과 파일 쓰기를 수반하므로 사용자가 요청한 경우에만 실행한다.
- 데이터와 체크포인트가 없으면 심볼 모델 성능을 추정하거나 검증 완료로 보고하지 않는다.

## 통합 QA와 프론트엔드

- `QA/run_qa_batch.py`는 실행 중인 백엔드에 요청하고 결과 CSV를 쓴다. 서버와 데이터셋 경로가 명시된 경우에만 실행한다.
- AI 단위 QA와 백엔드 통합 QA의 정확도는 측정 범위와 허용오차가 다르므로 합산하지 않는다.
- Flutter 의존성 설치·업데이트와 플랫폼 빌드는 네트워크, SDK 캐시, 생성 파일을 변경할 수 있으므로 필요한 이유를 먼저 설명한다.

## 비밀값과 보고

- 출력 금지: 토큰, 서비스 계정, 자격증명 내용, 사용자 개인정보, 민감한 로컬 절대 경로
- 출력 가능: 저장소 상대 경로, 공개 환경변수 이름, 비민감 설정값, 커밋 해시, 테스트 수치
- 비밀 설정은 값 대신 설정됨·비어있음만 보고한다.

## 사고 대응

- 외부 호출, DB 변경, 대량 파일 생성이 예상과 다르게 시작되면 추가 작업을 중단하고 실제 변경 범위를 확인한다.
- 사용자 파일이나 로컬 데이터가 영향을 받았으면 임의 복구를 시도하기 전에 상태와 복구 선택지를 보고한다.
